# Alloy log pipeline

> Area rules for `app/configmap.yaml`. Repo-wide rules are in `.github/copilot-instructions.md`.

## Testing a pipeline change

**Alloy pipeline (`kubernetes/apps/monitoring/alloy/app/configmap.yaml`)** — steps 1–4 only render the ConfigMap, and `alloy validate` checks syntax, not behaviour: a `stage.match` selector written with a backtick-quoted line filter validates and then fails at `run`, and every Alloy pod hot-reloads this one file, so a bad selector stops log shipping cluster-wide. Run the changed `loki.process` block against sample lines in a throwaway `grafana/alloy` container (the version the chart deploys): feed it with `local.file_match` + `loki.source.file`, end in `loki.echo`, and check which lines are kept and dropped, the counters on `/metrics`, and that no `__tmp*` label leaks. Write match selectors as double-quoted LogQL strings and avoid backslashes in the regex (`[.]`, `[]]`).

How to run it, in order:

1. Extract `data."config.alloy"` from the ConfigMap with Python and cut out the `loki.process` block. Wrap it with `local.file_match` and `loki.source.file` (set the labels in `path_targets`) and end in `loki.echo`.
2. `docker run --rm --name alloytest -p 12345:12345 -v "$DIR:/t:ro" grafana/alloy:<chart version> run --storage.path=/tmp/a --server.http.listen-addr=0.0.0.0:12345 /t/test.alloy > out.txt 2>&1 &`, then `sleep 20`, `curl localhost:12345/metrics`, `docker stop alloytest`. macOS has no `timeout`; entries show up as `entry=` lines in the output. Docker rejects a one-character container name (`--name t` fails with `Invalid container name`, checked 2026-11-26). Use the tag the DaemonSet runs (`kubectl -n monitoring get ds alloy -o jsonpath='{.spec.template.spec.containers[0].image}'`: v1.22.0 on 2026-11-26), not a tag inferred from the chart version.
3. Check the kept and dropped lines, **and** that no `__tmp*` label leaks.

**A `discovery.relabel "pods"` change is tested the same way, with the targets made up** (done for the namespace/pod/container/workload labels, 2026-11-26). Take the `discovery.relabel`, `local.file_match`, `loki.source.file` and `loki.process` blocks verbatim from the ConfigMap, replace `discovery.kubernetes.pods.targets` with a literal list of maps carrying the `__meta_kubernetes_*` labels the rules read (namespace, pod name and uid, container name, container id `containerd://x`, controller kind and name, and for a static pod the `..._annotation_kubernetes_io_config_hash`), and end in `loki.echo`. A multi-line Alloy list needs a trailing comma after its last element (`missing ',' in expression list` otherwise). Give each target a log file `<dir>/pods/<ns>_<pod>_<uid>/<container>/0.log` of CRI lines (`2026-11-26T12:00:00.000000000Z stdout F text`; a static pod's directory is named with the config.hash value) and mount `<dir>/pods` at `/var/log/pods`. Use one pod per owner kind (CronJob Job, bare Job, ReplicaSet, StatefulSet, DaemonSet, static pod, bare pod). Then run the same harness on `git show origin/main:<configmap>` and compare: a change that only adds labels must leave the number of distinct (instance, stream) pairs unchanged, and the `entry=` lines show the labels each stream gets. `alloy validate` on the generated file catches syntax only.

**Changing the labels a `discovery.relabel` target carries re-reads every current log file.** `loki.source.file` keys its read position by path *and* labels (`positions.yml` entries have both). Test it by pointing a run at a persistent `--storage.path` volume: a second run with the same config emits 0 entries, a run with new labels emits them all again (2026-11-26). The re-read lands in new streams, so Loki does not dedupe it against the old ones: lines from before the change show twice in queries that match both. The cost is bounded: on 2026-11-26 the five Alloy pods read 111MB in total since their restarts that morning, and that restart re-read every file already, so Loki (peak 515MiB of its 1Gi limit over 14d) has taken that burst before. A label added in `loki.process` or a `loki.relabel` after it does not change the key and re-reads nothing, but can only use labels the entry already has (no owner or controller metadata).

- **`stage.replace` replaces only the text a capture group matched.** An expression without a group changes nothing, and one with the wrong group edits the wrong part (`^information(al)?$` turned `informational` into `informationinfo`; fixed 2026-11-27). Test a level change with one fake JSON line per spelling (`Information`, `informational`, `Warning`, `WARNING`, `Critical`, a `LogLevel` and a `severity` key, klog `I`/`W`/`E`/`F`, a logfmt line, a line with no level) and compare the `structured_metadata` `level` of each against `git show origin/main:<configmap>`. A logfmt `level=warning` gets no `extracted_level` (`stage.json` fails on it), so these stages never touch it.
- A bad selector in the first test showed up as `invalid selector syntax for match stage ... unexpected IDENTIFIER, expecting STRING` at `run`, after `alloy validate` exited 0 (PR #890, 2026-10-25). Write the selector as `\"...\"` inside the Alloy string.
- **`stage.metrics` counters are labelled by the entry's label set, not by extracted values.** To split a counter by `action`, `stage.labels` it first; the metric is then `loki_process_custom_<name>`, exposed on each Alloy pod's own `/metrics`. Aggregate with `sum by`, because the UDP route spreads packets over all pods. `stage.sampling` reports its drops as `loki_process_dropped_lines_total{reason=...}`.
